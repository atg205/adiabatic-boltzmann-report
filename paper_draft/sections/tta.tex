\section{Time-to-accuracy over $N$, $h$, and $\epsilon$}
\label{sec:tta}

\subsection{The existing statistic underestimates retry cost}
\label{sec:tte-issue}

The source report's crossing statistic (Eq.~\eqref{eq:rollingmean}) is converted into a $99\%$-confidence time-to-solution by treating an unsuccessful seed as a full restart at the median successful time:
\begin{equation}
\mathrm{TTE}_{99}=
\begin{cases}
T_r, & p=1,\\[2pt]
T_r\,\dfrac{\ln(0.01)}{\ln(1-p)}, & 0<p<1,
\end{cases}
\label{eq:tte99}
\end{equation}
implemented exactly this way in \texttt{scripts/viz/paper\_figures.py}, function \texttt{tte99\_from\_validated()} (lines 148--174): a failed seed is simply excluded from the set whose median defines $T_r$ and is accounted for only through $p$. This is the standard retry formula for attempts of a \emph{fixed} runtime, but here a successful attempt can stop early at $t^\star$ while an unsuccessful one consumes the full $100$-iteration budget, and $T_r$ is computed only from the (generally shorter) successful attempts -- so the formula omits the cost of the failed full-budget runs it is nominally accounting for. This matters exactly where the reported crossover is claimed: at $N=64$, the reported successful fractions are FPGA $19/20$, Zephyr(+CEM) $19/20$, SA $18/20$, Metropolis $17/20$, Gibbs $16/20$, so between one and four unsuccessful seeds enter the ranking through $p$ alone. Exact binomial 95\% intervals at these counts are wide (e.g.\ $19/20\Rightarrow p\in[0.751,0.999]$), so the sharp distinction the current formula draws between, say, a $20/20$ and a $19/20$ series is not statistically supported by the underlying counts.

We initially tried repairing Eq.~\eqref{eq:tte99} directly, replacing the single successful-seed time $T_r$ with a fixed per-attempt cutoff $\tau$: $p_\tau=\Pr(T\le\tau)$, $T_{99}(\tau)=\tau\ln(0.01)/\ln(1-p_\tau)$, minimized over a grid of $\tau$. Re-run on the archived per-seed histories (no new device time needed), this by itself already overturns part of the reported headline: at $N=64$, $h=0.5$, $\epsilon=0.1$, the corrected statistic gives FPGA $2.78\,\mathrm s$ (95\% bootstrap CI $[1.45,3.71]$) against its originally reported $0.87\,\mathrm s$, while Pegasus(+CEM) and Zephyr(+CEM) move only slightly ($0.47\to0.58\,\mathrm s$ and $1.28\to1.27\,\mathrm s$) -- because FPGA's 19 successful seeds cross $\epsilon$ anywhere between $0.32\,\mathrm s$ and $1.75\,\mathrm s$, so the formula's $T_r$ (their median, $0.56\,\mathrm s$) understates what a real per-attempt cutoff has to be to actually realize a 95\% success rate.

We do not adopt this fixed-cutoff estimator as the paper's reported statistic, however: minimizing $T_{99}(\tau)$ over a dense, data-driven grid of $\tau$ -- rather than over $\tau$ values fixed \emph{before} looking at the data, as a fully rigorous version would require -- is itself a mild form of selection on the same 20-seed sample being evaluated, and the resulting point estimate can run optimistic even though the bootstrap CI (which re-does the full minimization on each resample) correctly reflects the extra variance this introduces. Rather than defend a specific choice of $\tau$-grid and pre-registration, we replace the single retry-adjusted number with the object it is trying to summarize in the first place: the achieved-error-vs-time curve.

Figure~\ref{fig:error-vs-time-grid} plots, for every solver at $N\in\{8,16,32,64\}$, the median (and IQR band, 20 seeds) energy error per spin against cumulative sampling time, with the $\epsilon=0.1$ (and $0.05,0.02,0.01$) tolerance lines marked directly on the same axes. This makes the criterion dependence of Sec.~\ref{sec:eps-h} visible for free -- reading off any $\epsilon$ is just reading a different horizontal line off the same curve -- and requires no retry model at all: a reader can see directly which solver's curve crosses a given tolerance first, at what time, and with how much seed-to-seed spread, without collapsing that information into one contested scalar.

\paragraph{Caveat on this figure.} Every seed's history is logged for the complete, fixed 100-iteration budget regardless of outcome (\texttt{stop\_at\_convergence=False} in the audited implementation), so no seed is actually missing data -- but once a seed's own run ends, its curve is held flat at its last recorded value for any later $\tau$ shown on the shared axis, rather than being extrapolated from new data. For a seed that never reaches $\epsilon$, this correctly keeps it contributing a still-failing value to the median/IQR at every later $\tau$ (it does not quietly drop out), but the specific held value past a seed's own duration is last-observation-carried-forward, not a measurement of what that seed would have done with more iterations. This figure is also scoped to $h=0.5$ only; Sec.~\ref{sec:eps-h} below still applies to the $h$ dimension.

\subsection{Criterion dependence: $\epsilon$ and $h$}
\label{sec:eps-h}

The reported crossover uses a single cell: the 1D TFIM at $h=0.5$ with $\epsilon=0.1$ per spin (a total-energy tolerance of $6.4$ at $N=64$). The target distribution changes qualitatively across $h$ -- strongly peaked in the ordered phase, approaching uniform at large field -- so a result at $h=0.5$ is not presumptively representative of the critical or paramagnetic regime. A sweep over $h\in\{0.5,0.7,0.9,1.0,1.1,1.3,1.5\}$ at fixed $N=16$ already exists in code, \texttt{fig\_tte\_vs\_h\_n16()} in \texttt{scripts/viz/paper\_figures.py} (lines 1469--1541), but it is defined and never invoked -- it does not run as part of the current figure-generation pipeline, and it fixes $\epsilon=0.1$ rather than sweeping it. No script anywhere sweeps $\epsilon$ (every figure function hardcodes a single value, $0.1$ for the validated-convergence figures and $0.01$ for the unrelated ITE figures).

Figure~\ref{fig:error-vs-time-grid} above resolves the $\epsilon$ half of this concern at $h=0.5$: because it plots achieved error continuously against time, every $\epsilon\in\{0.1,0.05,0.02,0.01\}$ is already readable off the same curves, for every tested $N$, with no additional reruns. The $h$ half is not resolved and is scoped explicitly out of this draft's central claim: as agreed, the correction above is stated for $h=0.5$ only, and whether it holds at other fields is left as an open, explicitly flagged question rather than silently assumed.

\subsection{Fixed-protocol vs.\ solver-optimized comparison}

The classical baselines are matched on outer SR settings but not on inner sampling effort: Metropolis restarts with 200 warm-up sweeps plus one sampling sweep, persistent Gibbs uses ten block sweeps after a one-time initialization, and simulated annealing uses 200 warm-up plus 40 cooling sweeps. This fixed-protocol comparison is scientifically useful on its own terms but is not the best-achievable time-to-accuracy of each sampler; sampling-quality figures elsewhere in this project (Fig.~\ref{fig:classical}) show simulated-annealing quality still improving well past 40 sweeps. \missing{\textbf{Solver-optimized comparison.} A second benchmark in which every classical sampler receives the same hyperparameter-tuning budget and independently minimizes its own time-to-accuracy, rather than sharing the outer protocol, is not implemented and is listed as a distinct experiment rather than an edit to the existing one.}
